### Added

- **Stale integrity block stripped on load (#105).** When a document is loaded into the reference editor — from a sample, an opened file, or a restored local draft — any trailing `<!-- portable-ai:integrity ... -->` block is removed and a quiet status line notes it. The integrity block is optional (Core spec §7) and derived content (ADR-0003); because the editor does no hashing, keeping a block after edits would leave a stale hash, which §10 forbids. Stripping it on load makes every subsequent edit — including Add section — safe by construction, with no cryptography in the client. The strip runs in the shared `setEditorValue` load path so all three entry points are covered, and the regex only matches a block at the very end of the document so body mentions of "integrity" are never touched. Full `crypto.subtle` SHA-256 support is noted as a possible post-RC follow-up. Smoke tests extended to 149 assertions (Case 18: end-of-document strip, body-mention safety, status note, and round-trip across all three load paths).
- **"Add section" button in the reference editor (#23).** Appends a new `# New section` heading to the end of the document, switches to Edit, and drops the cursor on the blank line beneath the heading so you can type the section name and content immediately. Always appends to the end — predictable and position-agnostic — rather than guessing from the cursor or nearby content. Sections are H1 (`#`) to match every shipped document and template. Per ADR-0007, the section's key is simply derived from whatever you rename the heading to, so there is nothing else to configure. Shown only when the editor has content, alongside Copy Markdown and Clear. Smoke tests extended to 144 assertions (Case 17: visibility gating, append behavior, Edit-mode switch, caret placement, and Read/download round-trip).

Raw HTML in the source is escaped, so the preview is safe for Markdown from untrusted authors (#53).

- **Tabbed reference editor**: the editor is now organized into three tabs — **Form**, **Markdown**, and **Preview** — that all edit the same underlying Markdown document. The Form tab renders structured inputs for each well-known section from the [Registry v1](spec/registry/well-known-sections-v1.md), including "+ Add" buttons for well-known sections not yet in the document. The Preview tab renders the parsed front-matter as a compact metadata card at the top of the preview instead of leaking raw YAML into the Markdown body.
- Persona template now ships with placeholder `e.g.` bullets under every well-known section so first-time users see what belongs in each section. Users replace or delete them (#22).
- **Empty-state landing** in the reference editor: fresh visitors now see "Nothing loaded yet · Load a profile or create a new one" with two equal-weight actions (**Load a sample**, **Open a file**) plus a secondary card that previews the AI-draft prompt with "Copy prompt" and "Show full instructions".
- **Restore-or-clear banner**: when a local draft exists in the browser, the editor no longer silently repopulates. It shows "You have a draft from a previous session." with **Restore** and **Clear** buttons so users can decide.
- **Edit / Read mode toggle** replaces the old Form / Markdown / Preview tab strip. The editor now has a single Markdown surface toggled between an Edit view (textarea) and a compact Read view.
- `docs/archive/` — folder for frozen historical documents (planning snapshots, audits) with a README explaining its read-only nature. First entry: `docs/archive/2026-07-06-issue-grouping-plan.md`, the issue-triage and working-set plan captured on 2026-07-06.
- **Left-margin teleport gutter in the reference editor (#83)** — a quiet, block-level affordance for moving between Edit and Read at the same spot. Each top-level Markdown block (heading, list, paragraph, etc.) gets a narrow vertical rectangle in the left margin; hovering or keyboard-focusing it lights it in accent blue, and clicking (or Enter/Space) switches to the other view and lands on the same block at roughly the same on-screen position. Bars are real, focusable `<button>`s. Clicking the editor text or the rendered preview body never toggles the view, and the header Edit|Read toggle is unchanged. Ships with two fictional sample profiles for testing under `examples/profiles/` — a Persona (`persona-jordan-rivera.md`) and a Software Project (`software-project-tidesynth.md`).
- **"Get a Prompt" page** (`website/get-a-prompt.html`) — a dedicated page, linked first in the site nav, for getting an extraction prompt to hand to any AI you already use. A profile-type selector lets you choose the kind of profile to extract — **Persona** or **Software Project** — and the full prompt is shown in a read-only readout (no scroll box) with **Copy prompt** buttons above and below. Prompts are written to pull as much durable, reusable context as possible and to return spec-valid Markdown (front-matter + well-known H1 sections) with the standard filename; neither asks for your name. All prompt wording now lives in a single source of truth, `website/js/prompt.js` (`window.PORTABLE_AI_PROMPTS`), shared by both the page and the editor, and the selector is data-driven so more profile types can be added by editing that one file. The empty-state "Ask an AI to draft one" flow and a new **Generate a new one** action now route here instead of opening a modal (#75).

### Changed

- **Sample profile ships with a real date, not a `YYYY-MM-DD` placeholder (#110).** The bundled persona sample loaded by "Load a sample profile" (and the `templates/portable-ai-persona-template.md` it mirrors) now carries `last_updated: 2026-07-07` instead of the literal `YYYY-MM-DD` token, so the Read-mode metadata card reads as a finished document rather than a fill-in-the-blanks form. The two `examples/profiles/` samples already carried real dates and were unchanged. Smoke tests assert the metadata card contains a real ISO date and no `YYYY-MM-DD` placeholder (151 assertions).
- **Consistent profile-centric terminology across the site (#111).** "Profile" is now the single primary noun everywhere; the bundled example is a "sample profile" and the `.md` file itself is a "profile document." "Markdown" is used sparingly — only where it names the raw format precisely (the Copy Markdown button, the Learn page's format definitions, the raw-text accessibility labels) rather than as the default word for the thing you own. Updated the editor blurb, empty-state action ("Load a sample profile"), Generate-a-Profile steps, Learn page copy, and editor status/confirm strings accordingly. Reference site copy only; no spec or file-format change.
- **Spec: sections are H1 (`#`), not H2 (`##`) (#104).** Corrected Core spec §5.1 (and the §5.3 custom-section definition plus the custom-key examples in the Persona and Software Project specs) to say a section is an H1 (`#`) heading, matching every shipped document and template — which have always used `#` for top-level sections and reserved `##`/`###` for grouping inside a section. Added an explicit note that deeper headings may appear inside a section as ordinary content without starting a new section. Erratum aligning the spec to reality; non-breaking (no document changes, no ADR required).
- **Custom sections drop reverse-DNS (#23, ADR-0007).** Reconciled the spec set to remove the reverse-DNS keying requirement for custom sections. Custom keys are now plain `snake_case` derived from the heading — no namespace, `.`, or `/` — matched case-insensitively, using the same rule as well-known keys. Duplicate-key headings in one Document are the author's choice and both are preserved verbatim (Core §10, unchanged). Updated Core spec §5.1/§5.2/§5.3 and its front-matter example, the Persona and Software Project specs, and Well-Known Section Registry v1. Spec-only change; no samples or templates used reverse-DNS body keys, so none needed migration.
- **Informative footer with version + build date (#43).** The site footer now shows the current version (`v0.3.0-rc.1`) and a build/update date alongside the existing open-source message and links, on all three pages. Both values come from a single source of truth, `website/js/version.js` (`window.PORTABLE_AI_VERSION`), stamped into the footer by `header.js`; the static HTML carries fallback text so the footer degrades gracefully with no JS. The build date renders as a machine-readable `<time datetime>`. Declined to add a place-of-origin line to keep the footer quiet. Smoke tests extended to 136 assertions (footer version + build date on all three pages).
- **Documentation consistency pass (#26).** Normalized the brand to one word — "PortableAI" — in `CONTRIBUTING.md` and `CODE_OF_CONDUCT.md` (were "Portable AI"). Reframed WHY.md's scope section from "What this project is not" to "What this project is", leading with what PortableAI does and keeping the scope boundaries as a positive rationale rather than a non-goal list.

No new on-screen UI — the guidance lives in the existing confirm step to keep the editor uncluttered. Satisfies the last open acceptance criterion for local profile persistence.
