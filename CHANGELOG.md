The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

- **Software Project spec v0.3 (DRAFT)** — `spec/portable-ai-software-project-spec-v0.3.md` — a second profile type derived from Core, capturing durable software-project knowledge (overview, architecture, tech stack, conventions, domain glossary, key decisions, constraints, environments, dependencies) so it can be handed to any AI without re-briefing. Reserves `document_type: software-project` in the Core spec (§4.3) and adds Software Project document keys to the Well-Known Section Registry (§4.2, additive within v1) (#73, #74)
- **Well-Known Section Registry v1 (DRAFT)** — `spec/registry/well-known-sections-v1.md` — centrally assigned `snake_case` section keys, additive within v1 (#47)

- Project email identity at `portableai.org`: `inbox@` mailbox with aliases `security@`, `hello@`, `maintainers@`
- `README.md` Contact section and `GOVERNANCE.md` Contact section
- Website footer contact links to `hello@portableai.org` and `security@portableai.org`
- Reference editor now renders full GitHub-Flavored Markdown in the live preview via vendored `marked.js` v14.1.4 — headings, lists, tables, fenced code with language classes, task lists, and inline formatting all render correctly. Raw HTML in the source is escaped, so the preview is safe for Markdown from untrusted authors (#53).
- `THIRD_PARTY_NOTICES.md` — attribution for vendored third-party code (currently `marked.js`, MIT)
- **Tabbed reference editor**: the editor is now organized into three tabs — **Form**, **Markdown**, and **Preview** — that all edit the same underlying Markdown document. The Form tab renders structured inputs for each well-known section from the [Registry v1](spec/registry/well-known-sections-v1.md), including "+ Add" buttons for well-known sections not yet in the document. The Preview tab renders the parsed front-matter as a compact metadata card at the top of the preview instead of leaking raw YAML into the Markdown body.
- Persona template now ships with placeholder `e.g.` bullets under every well-known section so first-time users see what belongs in each section. Users replace or delete them (#22).
- **Empty-state landing** in the reference editor: fresh visitors now see "Nothing loaded yet · Load a profile or create a new one" with two equal-weight actions (**Load a sample**, **Open a file**) plus a secondary card that previews the AI-draft prompt with "Copy prompt" and "Show full instructions".
- **Restore-or-clear banner**: when a local draft exists in the browser, the editor no longer silently repopulates. It shows "You have a draft from a previous session." with **Restore** and **Clear** buttons so users can decide.
- **Edit / Read mode toggle** replaces the old Form / Markdown / Preview tab strip. The editor now has a single Markdown surface toggled between an Edit view (textarea) and a compact Read view.
- `docs/archive/` — folder for frozen historical documents (planning snapshots, audits) with a README explaining its read-only nature. First entry: `docs/archive/2026-07-06-issue-grouping-plan.md`, the issue-triage and working-set plan captured on 2026-07-06.
- **Left-margin teleport gutter in the reference editor (#83)** — a quiet, block-level affordance for moving between Edit and Read at the same spot. Each top-level Markdown block (heading, list, paragraph, etc.) gets a narrow vertical rectangle in the left margin; hovering or keyboard-focusing it lights it in accent blue, and clicking (or Enter/Space) switches to the other view and lands on the same block at roughly the same on-screen position. Bars are real, focusable `<button>`s. Clicking the editor text or the rendered preview body never toggles the view, and the header Edit|Read toggle is unchanged. Ships with two fictional sample profiles for testing under `examples/profiles/` — a Persona (`persona-jordan-rivera.md`) and a Software Project (`software-project-tidesynth.md`).
- **"Get a Prompt" page** (`website/get-a-prompt.html`) — a dedicated page, linked first in the site nav, for getting an extraction prompt to hand to any AI you already use. A profile-type selector lets you choose the kind of profile to extract — **Persona** or **Software Project** — and the full prompt is shown in a read-only readout (no scroll box) with **Copy prompt** buttons above and below. Prompts are written to pull as much durable, reusable context as possible and to return spec-valid Markdown (front-matter + well-known H1 sections) with the standard filename; neither asks for your name. All prompt wording now lives in a single source of truth, `website/js/prompt.js` (`window.PORTABLE_AI_PROMPTS`), shared by both the page and the editor, and the selector is data-driven so more profile types can be added by editing that one file. The empty-state "Ask an AI to draft one" flow and a new **Generate a new one** action now route here instead of opening a modal (#75).

### Changed

- **Local-persistence "Clear" now explains the shared-computer use case (#32).** The clear-draft confirmation dialog was extended to note that clearing is useful on a shared computer and that the action can't be undone (download first to keep the draft). No new on-screen UI — the guidance lives in the existing confirm step to keep the editor uncluttered. Satisfies the last open acceptance criterion for local profile persistence.
- **Edit view now auto-grows to fit its content (#83).** The Markdown textarea no longer scrolls internally on a fixed height; it grows to show the whole document and the page scrolls instead. This puts Edit and Read in one coordinate space, so the teleport gutter can align to every block in both views without viewport clipping. The Read preview likewise grows with its content rather than scrolling inside a fixed box.
- **Internal naming clean sweep to match the UI (#86).** With the project not yet public (no external links to preserve), aligned behind-the-scenes names with the visible labels so there is no drift. Renamed the nav item **Project → GitHub** on all three pages. Renamed the destination page files `get-a-prompt.html → generate-a-profile.html` and `js/get-a-prompt.js → js/generate-a-profile.js`, updating every `href`/`src` and comment reference. Renamed the empty-state element IDs to match their labels: `empty-generate-new → empty-generate-profile` and `open-file → open-profile` (with the matching `openFileButton → openProfileButton` in `app.js`). Added semantic IDs to the three header nav links (`nav-generate-profile`, `nav-learn`, `nav-github`) so every primary nav item is addressable. Removed dead code: the unused `contextExportPrompt` constant and a disabled `if (false)` empty-state-preview block in `app.js`. Updated stale friendly-name comments ("Get a Prompt page" → "Generate a profile" page) across `app.js`, `prompt.js`, `generate-a-profile.js`, and `site.css`. The prompt-content IDs on the destination page (`prompt-title`, `prompt-readout-*`, `copy-prompt-*`, `type-options`, `prompt-status`) and `js/prompt.js` are intentionally kept — they accurately describe the prompt that page hands you to copy. Smoke tests (117/117) and the screenshot harness were updated to the new selectors and filenames.

- **Editor home copy tidy (#86).** Removed the in-body "Learn more" (hero tagline) and "Read more" (editor blurb) links, since the header nav already links to the Learn page. In the empty state's "Ask an AI to draft one" block, removed the standalone "Get a prompt" link and replaced the hint with `Click "Generate a new one" to build your profile from any AI.` (the "Generate a new one" action still opens the Get a Prompt page). The block heading is unchanged. Reordered the empty-state primary actions to **Generate a profile · Open a profile · Load a sample** and renamed "Open a file" to "Open a profile". Unified the wording for the profile-generation destination on **"Generate a profile"** everywhere it is user-visible — the header nav item (all pages), the destination page `<h1>` and `<title>`, and the empty-state action and hint — replacing the earlier mix of "Get a Prompt" and "Generate a new one". The destination page still explains the mechanism (it hands you a prompt to send to an AI you already use).

- **Spec finalization (Group 1 — #44).** Renamed the last remaining "specification" in the live Core spec to "Spec" (the `document_type: spec` description now reads "a PortableAI Spec document"). The frozen v0.2 monolithic persona spec is intentionally left unchanged as a migration reference (retired later under #27), and the one remaining occurrence in `learn.html` is kept as ordinary prose. Verified #51 (content filenames already kebab-case) and #52 (`document_type: patch` already reserved in the Core spec) require no further changes.

- **Fixed header, flatter type, and site-wide link color (PR A4)**. Added a `position: fixed` top header to both `index.html` and `learn.html`: a **PortableAI** wordmark on the left linking home, and two right-side links — **Learn more** (`/learn.html`) and **Project** (the GitHub repo). Two items only for now. On screens ≤640px the links collapse behind a hamburger that toggles a small slide-down panel (`website/js/header.js`); `.page` gained top padding so the hero clears the fixed header. The now-redundant "← Back to the editor" nav at the top of `learn.html` was removed. Flattened regular text to a single size and color: the hero sub-tagline, editor blurb, empty-state helper, and both footer lines are now `1rem` `#111` (footer meta un-muted). Links are accent-blue site-wide; the only remaining muted action is the **Close** button in the AI-draft overlay. Footer is left-aligned and its container width matches `.page` (880px) so it sits flush with the editor box above. Smoke tests extended to 99 assertions (header on both pages, flattened type, link colors, single muted Close, footer alignment, mobile hamburger); screenshot harness adds `07_header_mobile.png` (375×812).

- **Density + copy pass (PR A3)**. Hero shrunk dramatically: H1 now `clamp(1.6rem, 3.2vw, 2rem)` with matching proportional tagline, and rephrased to "Every AI needs you to start over. They don't ask." A **Learn more** link now sits inline with the tagline and routes to a new `/learn.html` explainer page covering what PortableAI is, why it exists, what's in a profile, how the reference editor works, the Non-Storage Principle, and how to use it. Removed the hero action links (Ask an AI / Open the editor) entirely — the empty state below handles those flows. Cut the "Edit your profile" H2; the editor now leads with a single sentence, "Your profile is a Markdown file you own. Edit it here, then download it and take it anywhere. Your profile is never stored on PortableAI. Read more." Removed the standalone privacy-and-trust box. Page max-width tightened to 880px and empty state left-aligned so content sits under the opening text instead of floating in whitespace. AI-draft overlay: **Copy prompt** now sits above the textarea alongside a **Show full prompt** toggle; the textarea starts collapsed at ~6 lines and expands on click, so the overlay fits on one screen without scrolling. Overlay intro rewritten to "…open on PortableAI.org". Footer tagline replaced with a repo + license + version meta line (MIT · GitHub · v0.3-draft) plus contact links; the "People should own their context" tagline is retired from the footer.

- **Design tone: quiet, minimalist link-style actions (PR A2)**. Replaced the harsh black-and-white `.button` style with underlined blue `.link` (primary) and muted-gray `.link.muted` (secondary) actions throughout the editor, hero, empty state, restore banner, and AI-draft overlay. Paired actions now sit together on one line with a `·` separator so possible workflows read at a glance ("Load a sample · Open a file", "Restore · Clear", "Copy prompt · Show full instructions"). Removed decorative eyebrow labels (PORTABLEAI.ORG, BROWSER-ONLY REFERENCE EDITOR, ASK AN AI TO DRAFT YOUR PROFILE, "Reusable draft prompt") that took up room without doing work; kept the DOCUMENT METADATA eyebrow in Read mode because it signals the informational card below. Metadata values now render in muted gray to signal they are informational, not editable. Overlay workflow list rewritten to four concrete steps. Accent color moved from `#2447ff` to `#3b5bff` (with `#2d47db` hover) and neutral border lightened to `#e2e5ea` for a softer read.

- **Reference editor redesign (PR A)**: dropped the Form tab entirely — the Markdown document is the only editing surface. Introduced Edit / Read modes, an empty state, and a restore-or-clear banner (see Added). Read mode uses a tighter type ramp (body 0.95rem, H1 1.15rem, H2 1.05rem, H3 0.95rem — all bold, 1.5 line-height) so profiles read like documents, not splash pages.
- **AI-draft prompt rewritten** to actively ask another AI to draft a PortableAI profile: Markdown first (works in every AI), best-effort downloadable `.md` file, standard filename `portableai-profile-YYYY-MM-DD.md`. The prompt never asks the user's name. Closes with instructions the user can act on: "You can take this file and load it into another AI, or open it in PortableAI to review or edit."
- **UI copy: Persona → Profile** as the umbrella noun users see. Hero tagline is now "PortableAI is an open standard that lets you take your **profile** anywhere." Editor heading is "Edit your profile." Sample-load button is "Load a sample" (was "New from Template"). File-open button is "Open a file" (was "Load Markdown"). Front-matter `standard: PortableAI Persona` is unchanged — Persona remains one *type* of profile.
- **Download filename** standardized to `portableai-profile-YYYY-MM-DD.md` (was `portable-ai-persona.md`) so profiles from any session line up predictably on disk.

- File naming standardized to lowercase kebab-case:
  - `spec/Portable_AI_Persona_Specification_v0.2.md` → `spec/portable-ai-persona-spec-v0.2.md`
  - `templates/Portable_AI_Persona_Template.md` → `templates/portable-ai-persona-template.md`
  - `examples/Example_Portable_AI_Persona.md` → `examples/example-portable-ai-persona.md`
- `README.md` repo tree updated to reflect the new structure
- Renamed "Specification" to "Spec" in prose across `README.md`, `ROADMAP.md`, `CONTRIBUTING.md`, `SECURITY.md`, `CHANGELOG.md`, `adr/0000-project-inception.md`, `ai/codex-bootstrap.md`, and `ai/project-bootstrap.md` (#44). The frozen v0.2 spec file is unchanged.
- Reference editor preview: replaced the hand-rolled Markdown-subset renderer (headings + lists + inline bold/italic/code only) with vendored `marked.js` for full GFM support (#53)
- Reference editor: canonical Markdown remains the single source of truth (ADR-0001); all three tabs read from and write to the same in-memory string. Front-matter is no longer visible in the Preview — it appears as a metadata card instead. Guarded `localStorage` access so the editor no longer crashes when opened from an opaque origin (e.g. bare `file://`) or when storage is disabled by policy.
- Form tab now renders document metadata as a read-only card (matching the Preview) instead of editable text inputs. Front-matter values are still editable on the Markdown tab, keeping the canonical Markdown as the single source of truth.
