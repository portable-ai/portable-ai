# Profile

- Product manager and part-time community-college instructor based in Austin, Texas (US Central time).
- Works primarily in English; reads and writes intermediate Spanish and likes practicing it in low-stakes contexts.
- Ten years in B2B SaaS, the last four focused on developer-facing and data products.
- Prefers to be treated as a technical-enough generalist: comfortable reading SQL, API docs, and basic code, but not a full-time engineer.

# Preferences

- Wants concise answers first, with the option to expand — a short direct answer, then supporting detail underneath.
- Prefers plain language over jargon; when a term of art is unavoidable, define it once in-line.
- Likes concrete examples and small tables over long prose walls.
- For recommendations, wants one strong default plus at most one alternative, not a menu of ten options.
- Prefers Markdown for anything that might be reused, copied, or version-controlled.
- Dislikes filler, hedging, and restating the question back before answering.

# Persona

- Curious and pragmatic; optimizes for shipping something useful over perfect.
- Calm and direct in tone; appreciates respectful pushback and being told when an idea is weak.
- Dry sense of humor, but keeps work communication clear and low-drama.
- Comfortable with ambiguity as long as assumptions are stated out loud.

# Projects

- **Atlas** — leading the roadmap for a usage-based billing platform; currently untangling how to expose metering data to customers without overwhelming them.
- **Teaching** — runs an evening "Intro to Product Management" course each fall; reuses real (anonymized) cases from work.
- **Home data project** — a small personal dashboard that pulls together calendar, cycling, and reading data; a sandbox for trying tools before proposing them at work.

# Interests

- Developer experience and API design.
- Data visualization and the craft of making dashboards people actually read.
- Endurance cycling and training-load tracking.
- Language learning, especially spaced-repetition methods.
- Urban planning and public transit.

# Knowledge & Expertise

- Deep: B2B SaaS product management — discovery, roadmapping, pricing and packaging, stakeholder alignment.
- Strong: usage-based/metered billing models and their edge cases.
- Working: SQL for analysis, reading REST and GraphQL API docs, interpreting product analytics.
- Teaching: explaining product concepts to non-PMs and early-career folks.

# Decision Style

- Starts from the user problem and the metric that would move, then works backward to options.
- Writes a short one-page brief before big decisions; prefers async written proposals over live debate.
- Bias toward reversible, small first steps; will run a limited experiment before a broad rollout.
- Explicitly names trade-offs and the assumptions a decision depends on.

# Communication Style

- Async-first: prefers a well-structured written doc over a meeting when a meeting isn't required.
- Uses headers, bullets, and bold sparingly to make documents scannable.
- Likes a clear "recommendation / why / risks / next step" structure for proposals.
- In meetings, wants an agenda in advance and a written summary after.

# AI Collaboration Instructions

- Lead with the answer, then the reasoning — don't make me scroll to find the point.
- When you're uncertain, say so and state your assumption rather than inventing specifics.
- Prefer Markdown output I can paste into a doc or repo.
- Don't ask for my name or personal details you don't need; skip anything not durable.
- If a request is ambiguous, make one reasonable assumption, note it, and proceed — ask only if the assumption would meaningfully change the result.
- When giving options, give a clear default; I'll ask for more if I want them.
